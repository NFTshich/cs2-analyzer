# CS2 Analyzer

Аналитический инструмент для Counter-Strike 2: собирает матчи с открытых источников,
считает метрики, строит ML-модель для предсказания победителя и показывает результат
в веб-интерфейсе Streamlit.

## Возможности

- **Сбор данных** — реальные матчи с открытого API **Liquipedia** (без ключей)
  через `src/scraper.py` (режим `sync`). Для мгновенного запуска без сети доступна
  синтетическая заглушка (режим `mock`).
- **Фичи** — форма команды (**recency-weighted**, недавние матчи значат больше),
  winrate по картам, **map-specific Elo** (сила на каждой карте отдельно, blend
  с общим рейтингом), head-to-head, **ELO-рейтинги команд**, **strength of
  schedule**, pick-rate карт, **свежесть состава** (штраф за ротации),
  **средний персональный Elo и K/D состава** (по игрокам), **официальный
  мировой рейтинг команды** (Cito), разница рейтингов, recent form (30 дней),
  вес тира.

### Внешние данные (Cito API)

Подключён Cito API (CS2 статистика) — официальный мировой рейтинг команд и
индивидуальные статы игроков (K/D и др.) вливаются в фичи модели:
- `src/cito.py` — клиент с дисковым кэшем (бережёт лимит 500 запросов/мес);
- `fetch_cito_data.py` — рейтинг + составы топ-40 команд;
- `fetch_cito_players.py` — инкрементальная докачка K/D игроков;
- фичи `cito_rank`/`cito_points` (рейтинг команды) и `roster_kd` (K/D состава).

Ключ задаётся в `.env` → `CITO_API_KEY`.
- **ML** — LogisticRegression / RandomForest / GradientBoosting, валидация через
  `TimeSeriesSplit` (порядок матчей не перемешивается), калибровка вероятностей.
- **Backtest** — как модель работала на истории.
- **Streamlit UI** — 4 страницы: прогноз, форма, карты, backtest.

## Автообновление данных

Пока приложение запущено, фоновый поток **раз в час** (по умолчанию):
- докачивает новые сыгранные матчи с Liquipedia (инкрементальный merge, без дублей);
- при появлении новых матчей пересобирает фичи и переобучает модель.

Управление через `.env`:

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `CS2_AUTO_REFRESH` | `1` | вкл/выкл автообновление (`0` = выкл) |
| `CS2_AUTO_REFRESH_INTERVAL` | `3600` | период в секундах (3600 = 1 час) |

Модуль: `src/autorefresh.py`.

## Данные о составах

Liquipedia содержит составы команд-участников турниров (шаблон `TeamCard`).
Парсер извлекает их и сохраняет в `roster_a`/`roster_b` в `matches.csv`.
Признак **`roster_freshness`** (0..1) показывает, насколько давно состав команды
стабилен: 0 — только что была ротация (штраф), растёт к 1 при неизменном
составе. Если составов в данных нет — принимает нейтральное 0.5.

Пересобрать только составы без полного сканирования:
```bash
python patch_rosters.py
```

## Уровень уверенности прогноза

Модель возвращает не только вероятность, но и **уровень уверенности**,
который интерфейс показывает цветным уведомлением:
- **low** — вероятность фаворита < ~57.5%: шансы примерно равны или мало
  данных. Модель показывает предупреждение «результат близок к монете».
- **medium** — вероятность фаворита 57.5–65%: сигнал есть, но слабый.
- **high** — вероятность фаворита > ~65%: заметный перевес одной команды.

Точность модели (TimeSeriesSplit, ~2600 реальных матчей 2020–2026):
ROC-AUC ≈ **0.66**, accuracy ≈ **0.62** — после ввода ELO-рейтингов,
strength-of-schedule, свежести состава, map-specific Elo, расширения данных,
recency-weighted формы, ансамбля моделей и внешних данных Cito (мировой рейтинг
команд + индивидуальный K/D игроков). При этом киберспортивные матчи остаются
сильно стохастичными: даже лучшие букмекерские модели дают 60–70% на пару.

### Прогноз серии (BO3)

Для BO3 интерфейс использует **симуляцию вето карт**: предсказывается выбор
трёх карт (каждая команда банит худшую, пикает лучшую + десайдер) на основе
map-specific Elo, затем вероятности по картам комбинируются в вероятность
победы в серии. Это точнее, чем просто "среднее по картам".

### Ансамбль моделей

Прогноз усредняет вероятности RandomForest, GradientBoosting и
LogisticRegression (ансамбль), что стабилизирует результат и снижает
overfitting на одной модели. Файл `models/model.pkl` хранит словарь моделей.

### Инвариантность к порядку команд

Прогноз **не зависит от того, какую команду выбрать первой**: вероятность
усредняется по обоим порядкам (A→B и B→A), поэтому пары дают зеркальные
проценты. Раньше из-за сдвига в данных (команда A чаще побеждала) порядок
влиял на результат — исправлено зеркалированием датасета при обучении и
усреднением в `predictor.py`.

## Конфигурация

Всё настраивается в `src/config.py` и `.env` (префикс `CS2_`):

| Переменная              | Значение по умолчанию | Описание                          |
|-------------------------|-----------------------|-----------------------------------|
| `CS2_SCRAPER_MODE`      | `sync`                | `mock` (синтетика) / `sync` (Liquid) |
| `CS2_SYNTHETIC_MATCHES` | `1200`                | число матчей заглушки             |
| `CS2_REQUEST_DELAY`     | `250`                 | задержка между запросами (сотые с) |
| `CS2_LIQUIPEDIA_MAX_PAGES` | `40`               | лимит страниц турниров при авто-обходе |
| `CS2_MATCHES_RAW`       | `data/raw/matches.csv`| путь к сырым данным               |

Список страниц турниров для импорта задаётся в `src/config.py → LiquipediaConfig.tournament_pages`.
По умолчанию включено ~47 страниц крупных завершённых событий — сезоны ESL Pro League
(11–20, 22–23), IEM 2023–2025 (Katowice, Cologne, Dallas, Chengdu, Rio, Melbourne),
BLAST Premier 2022–2024, мажоры (BLAST Paris 2023, PGL Copenhagen 2024, Perfect World
Shanghai 2024, StarLadder 2025, PGL 2025), Esports World Cup, Thunderpick 2023–2024,
Gamers8 и другие — итого **~2600+ реальных матчей** (2020–2026) с учётом подстраниц.

Дополнительно можно влить открытые датасеты (HLTV-зеркала) без обращений к
заблокированным сайтам:
```bash
python import_external_dataset.py <путь_к_csv> [tier]
```
Формат csv — HLTV-зеркальный (одна строка на карту). Скрипт группирует карты
в матчи, дедуплицирует по паре команд + дате против текущей базы и доливает
только новые.

## Реальный источник (Liquipedia)

Liquipedia — открытая вики, собирающая данные турниров CS2. Прайс:

- Не нужны ключи: клиент `src/liquipedia.py` ходит в их MediaWiki API.
- Перечень завершённых турниров можно подтянуть автоматически по категории
  `Finished Tournaments` (см. `scrape_by_categories()`).
- Модуль уважает rate-limit (пауза `CS2_REQUEST_DELAY` между запросами).

> Важно: Liquipedia — не API с гарантиями доступа; при кратковременной недоступности
> scraper прозрачно откатится на синтетику, чтобы пайплайн не падал.
